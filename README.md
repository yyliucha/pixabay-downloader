# Pixabay Image Downloader

[![Python](https://img.shields.io/badge/Python-3.8+-blue.svg)](https://www.python.org/)
[![Docker](https://img.shields.io/badge/Docker-ready-2496ED.svg?logo=docker)](https://www.docker.com/)
[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)
[![GitHub last commit](https://img.shields.io/github/last-commit/yyliucha/pixabay-downloader)](https://github.com/yyliucha/pixabay-downloader)

Batch download images from [Pixabay](https://pixabay.com/) via the official API — keyword search, global dedupe (never re-download the same image), cron-based scheduled downloads, cross-platform, and one-command Docker deployment. Pure Python standard library, no third-party dependencies.

## Features

- ✅ **Official API** - stable and compliant, no browser automation or scraping
- ✅ **Global dedupe** - never re-downloads an image, guaranteed by two layers:
  - `download_history.json` records every downloaded image by its Pixabay image ID; downloaded images are **never re-downloaded**, even if you change keywords, change output folders, or move files around
  - File-existence check: existing target files are skipped (resume support)
- ✅ **Re-running fetches the next new images** - already-downloaded images are skipped automatically and pagination continues until all results for a keyword are exhausted
- ✅ **Scheduled downloads (cron, cross-platform)** - system cron on Linux/macOS, Task Scheduler fallback on Windows, built-in cron in Docker; one unified cron expression format
- ✅ **Environment-variable configuration** (`PIXABAY_API_KEY`, keywords, counts, sizes, directories, logging, etc.) - no code changes needed for Docker/server deployment
- ✅ **Multithreaded downloads** with automatic retries (3 attempts, exponential backoff)
- ✅ Four size tiers: **original / large (~1280px) / webformat (640px) / preview (150px)**
- ✅ A `metadata.csv` manifest is generated in each keyword folder (image ID, source page, tags, author, download URL, status)
- ✅ Pure Python standard library (**Python 3.8+**, no dependencies to install)
- ✅ `--dry-run` mode: search first and print URLs without downloading

## Quick Start

### Step 1: Get a free API key

1. Register a free account at https://pixabay.com/accounts/register/ (or sign in with Google/Facebook)
2. Open https://pixabay.com/api/docs/ - your API key is shown on this page
   (format: `1234567-abcdef0123456789abcdef01`)
3. Copy `.env.example` to `.env` and fill in your key:

```
PIXABAY_API_KEY=1234567-abcdef0123456789abcdef01
```

> Alternatively, set the `PIXABAY_API_KEY` environment variable, or pass `--key` on the command line.

### Step 2: Configure download options (optional)

Edit `config.json`:

| Key | Description | Default |
|---|---|---|
| `keywords` | Search keywords; each keyword gets its own subfolder | `["mountain", "landscape", "forest", "lake", "nature"]` |
| `per_keyword` | New images per keyword (on re-runs: how many MORE new images) | `50` |
| `image_size` | `original` / `large` (~1280px) / `webformat` (640px) / `preview` (150px) | `original` |
| `image_type` | `photo` / `illustration` / `vector` / `all` | `photo` |
| `safe_search` | Filter inappropriate content | `true` |
| `output_dir` | Image save directory | `F:/dsh/pixabay_images` |
| `workers` | Concurrent download threads | `4` |
| `api_delay_seconds` | Delay between search requests (increase if rate-limited) | `0.2` |

### Step 3: Run

```bash
# Download per config.json
python pixabay_downloader.py

# Or double-click run.bat (Windows)
```

Useful CLI options (higher priority than config.json):

```bash
python pixabay_downloader.py --keywords "mountain,landscape" --count 100
python pixabay_downloader.py --size large --output D:/pictures
python pixabay_downloader.py --dry-run      # search only, print URLs
python pixabay_downloader.py --quiet        # no per-image progress lines
python pixabay_downloader.py --log run.log  # also append output to a log file
```

## Re-running: Download More Images

Just **run it again** - no extra steps needed:

- Already-downloaded images are skipped (via `download_history.json`), and pagination **continues to the next new images**
- `per_keyword` / `--count` means "how many MORE new images to download"
- When all results for a keyword are exhausted, it reports `no new images to download`

Example: `--count 50` downloads the first 50 → run again with `--count 50` → downloads images 51-100 → each run moves further down the list, never repeating.

## Scheduled Downloads (cron, cross-platform)

One unified **cron expression (minute hour day month weekday)** across all platforms:

| Platform | Scheduling mechanism |
|---|---|
| Linux / macOS | System cron (`crontab` command, user-level, no root needed) |
| Windows | No native cron - automatically falls back to Task Scheduler (schtasks) |
| Docker | Built-in cron in the container (`CRON_EXPRESSION` env var) |

Combined with the "re-run fetches new images" mechanism, every scheduled trigger downloads the next batch of new images: **long-running = images keep accumulating, never duplicated**.

### Register a scheduled task

```bash
python setup_schedule.py --daily 02:00          # every day at 02:00
python setup_schedule.py --hourly 6             # every 6 hours
python setup_schedule.py --weekly "10:00 SUN"   # every Sunday at 10:00
python setup_schedule.py --cron "0 */2 * * *"   # raw cron expression (same as Docker CRON_EXPRESSION)
python setup_schedule.py                        # interactive wizard
```

### Manage the scheduled task

```bash
python setup_schedule.py --list                 # show the current scheduled task
python setup_schedule.py --remove               # remove the scheduled task
python setup_schedule.py --dry-run              # print the commands without applying
```

### Platform notes

- **Linux / macOS**: writes to your user crontab with a `# >>> PixabayDownloader start/end` marker block - re-registering replaces it automatically and your other crontab entries are untouched. Command output is redirected to `logs/cron_stdout.log`; download details go to `logs/pixabay_download.log`. Requires cron to be installed (present by default on mainstream distros).
- **Windows**: falls back to Task Scheduler (task name `PixabayDownloader`, runs only when the user is logged on by default). Cron expressions with month/day restrictions (e.g. `0 2 15 * *`) cannot be expressed on Windows; the tool prints a hint to use Docker or Linux/macOS instead.
- **Docker**: built-in busybox cron; `CRON_EXPRESSION` is the cron expression (default `0 2 * * *`), timezone controlled by `TZ`; logs go to `/data/logs` and `docker logs`.
- Each trigger downloads the next batch of new images (`per_keyword` per keyword); exhausted keywords are skipped without affecting others.
- After moving the project or upgrading Python, re-run `setup_schedule.py` to refresh the task.

## Docker Deployment (Recommended for Servers)

The container has built-in cron and downloads new images at a fixed time every day (global dedupe, never repeated) - ideal for long-running Linux servers.

### Build from source

```bash
# 1. Clone the repository
git clone https://github.com/yyliucha/pixabay-downloader.git
cd pixabay-downloader

# 2. Copy and edit the host config file (PIXABAY_API_KEY is the important one)
cp .env.example .env
vi .env

# 3. Start (set RUN_ON_START=true on first deploy to verify with an immediate run)
docker compose up -d --build

# 4. Watch the logs
docker compose logs -f
```

### Pull from Docker Hub (no clone, no build)

The image is **built and pushed to Docker Hub automatically by GitHub Actions** (push `main` → `latest`; push a `v*` tag → `vX.Y.Z` + `latest`; multi-arch: linux/amd64 + linux/arm64). Once the image is published, deploy on any server without cloning or building:

```bash
# Option A: single docker run command (downloads every day at 02:00)
docker run -d --name pixabay-downloader --restart unless-stopped \
  -e PIXABAY_API_KEY=your-pixabay-key \
  -e TZ=Asia/Shanghai \
  -e CRON_EXPRESSION="0 2 * * *" \
  -e PIXABAY_KEYWORDS="mountain,landscape,forest" \
  -v /server/images-dir:/data/images \
  -v /server/logs-dir:/data/logs \
  <DockerHubUsername>/pixabay-downloader:latest

# Option B: Compose (clearer config) - edit docker-compose.yml:
#   remove the `build: .` line and set image: <DockerHubUsername>/pixabay-downloader:latest
#   then: docker compose up -d   (pulls the image automatically)
```

**One-time setup for automatic image builds** (~2 minutes):

1. Sign in to [Docker Hub](https://hub.docker.com) → Account Settings → Security → **New Access Token** (permission: **Read & Write**)
2. On GitHub: repo → Settings → Secrets and variables → Actions → **New repository secret**, add two:
   - `DOCKERHUB_USERNAME` = your Docker Hub username
   - `DOCKERHUB_TOKEN` = the token from step 1
3. Done - the next push to `main` or a `v*` tag builds and pushes automatically. Until the secrets are configured, the workflow skips gracefully.

### Host configuration (.env file, all optional)

| Variable | Description | Default |
|---|---|---|
| `PIXABAY_API_KEY` | **Required**, Pixabay API key | - |
| `PIXABAY_KEYWORDS` | Search keywords, comma-separated | `mountain,landscape,forest,lake,nature` |
| `PIXABAY_COUNT` | New images per keyword | `50` |
| `PIXABAY_SIZE` | `original` / `large` / `webformat` / `preview` | `original` |
| `PIXABAY_IMAGE_TYPE` | `photo` / `illustration` / `vector` / `all` | `photo` |
| `PIXABAY_SAFE_SEARCH` | `true` / `false` | `true` |
| `PIXABAY_WORKERS` | Concurrent download threads | `4` |
| `PIXABAY_DELAY` | Delay between API requests (seconds) | `0.2` |
| `PIXABAY_TIMEOUT` | Per-image download timeout (seconds) | `60` |
| `TZ` | Container timezone (**scheduled triggers follow this**) | `Asia/Shanghai` |
| `CRON_EXPRESSION` | Cron expression: min hour dom month dow | `0 2 * * *` |
| `RUN_ON_START` | Run one download on container start (`true`/`false`) | `false` |
| `PIXABAY_HOST_IMAGES_DIR` | **Host images directory** | `./pixabay_images` |
| `PIXABAY_HOST_LOG_DIR` | **Host logs directory** | `./logs` |

> Config precedence: CLI arguments > environment variables > `config.json` > defaults. For more control, mount your own `config.json` (docker-compose.yml already maps `./config.json:/app/config.json:ro`).

### Logs and data

- **Complete logging, two channels**: container `/data/logs/pixabay_download.log` (mounted to host `./logs/`, with per-run timestamps and full search/download/dedupe/failure details) + `docker compose logs` (stdout mirror including cron triggers)
- Images: host `./pixabay_images/<keyword>/` (per-keyword subfolders + `metadata.csv` + global dedupe record `download_history.json`)
- Change config: edit `.env`, then `docker compose up -d` (no image rebuild needed)
- Update code: `git pull`, then `docker compose up -d --build`
- Remove service: `docker compose down` (host images/logs are kept)

### Management commands

```bash
docker compose logs -f                                   # tail logs
docker compose exec pixabay-downloader cat /etc/crontabs/root   # inspect the in-container cron
docker compose exec pixabay-downloader python pixabay_downloader.py --dry-run  # trial run
docker compose restart
```

## FAQ

| Issue | Solution |
|---|---|
| `invalid API key... Invalid API key` | Wrong or incomplete key; re-check `.env` (it is case-sensitive) |
| `rate limited (429)` | Increase `api_delay_seconds` in `config.json` to `1` or higher |
| Some images fail to download | Automatic retries (3x); just re-run - completed ones are skipped |
| Want more images for a keyword | Re-run: already-downloaded images are skipped and the next new ones are fetched, until all results are exhausted |
| Want to re-download downloaded images | Delete `download_history.json` (or the keyword subfolder) and re-run |
| Downloaded SVGs instead of photos | Set `image_type` to `photo` (default) |
| Scheduled task did not run | The machine was off/asleep at trigger time. Windows: enable "Run task as soon as possible after a scheduled start is missed"; Linux: use anacron for catch-up |
